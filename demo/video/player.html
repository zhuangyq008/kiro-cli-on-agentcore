kiro-cli on AgentCore

把 Kiro 的编码 agent 变成运行在你自己 AWS 账号里的异步服务

每个任务一个 microVM 结果进 S3，通知走 EventBridge 可选闭环和独立验证

在本地用 agent 写代码很方便，团队用起来有三个问题

1

占用开发者的电脑

任务运行的时候人只能等，任务一多就排不开

2

权限和结果分散

凭证、日志和产出留在每个人的机器上，难以管理和审计

3

接不进流水线

很难在 CI 里批量、无人值守地运行

把 kiro-cli 放到 AgentCore Runtime 上，变成一个异步服务

在 CI 里用机器账号提交任务（GitHub Actions）


- name: 让 agent 修复 issue 并提 PR
  env:
    KAC_CLIENT_ID: ${{ vars.KAC_CLIENT_ID }}
    KAC_CLIENT_SECRET: ${{ secrets.KAC_CLIENT_SECRET }}
    # 其余 KAC_* 配置见 docs/kac.md
  run: |
    TASK=$(kac submit "修复 issue #42 并提 PR" \
      --context "仓库: ${{ github.repository }}" \
      --ac "所有现有测试通过" \
      --loop-mode process)
    kac wait "$TASK"   # 退出码反映任务结果

      

    

  


  

    
安全：四点设计，一点需要了解

    

      
1
部署在你自己的账号
由 CloudFormation 管理，可以完整卸载

      
2
每个任务一个 microVM
任务之间不共享文件、进程和内存，结束后回收

      
3
任务默认没有 AWS 权限
需要时再按最小范围开启只读权限

      
4
登录后才能提交
用户由管理员创建，每个人只能看到自己的任务

    

    
需要了解　模型推理由 Kiro 服务完成，prompt 和 agent 读到的代码会发送过去。详见 docs/security.md

  


  

    
成本：主要是模型用量

    

      
约 $1 / 月
没有任务时
基础设施的固定费用

      
< $0.05
单次运行的小任务
问答、小函数、小改动

      
$2 – 2.5
闭环的代码任务
多文件改动加测试，20 到 30 分钟

    

    
测试环境的实测数据（2026 年 11 月）：约 94% 的费用是 Kiro credits。估算方法见 docs/cost.md
